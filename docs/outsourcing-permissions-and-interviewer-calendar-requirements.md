# 外包公司权限隔离与面试官时间看板需求说明（敲定版）

- 文档状态：已确认，V1.0 已实现并进入部署验证
- 版本：V1.0
- 确认日期：2026-08-04
- 适用项目：`hanzhihao83-lgtm/ats-interview-system`
- 需求范围：账号授权、数据隔离、应聘记录负责人、联系方式脱敏、管理员模拟视角、面试官账号、全局时间看板、约面冲突、不可用时间、站内与 Kim 通知

## 1. 背景与目标

平台同时服务多家外包公司。外包公司只能处理本公司且由当前账号负责的招聘数据，外包公司负责人可以查看本公司全部数据，平台管理员可以查看所有公司的招聘情况并配置权限。

面试官的时间不按外包公司隔离，而是全平台共享。任意一家外包公司占用某位面试官的时间后，其他公司只能看到该时间“已占用”，不得看到候选人或公司详情，也不得重复预约。

本期目标：

1. 建立“平台管理员 → 外包公司权限上限 → 外包公司账号实际权限”的授权链路。
2. 建立“所属外包公司 + 当前负责人”双重数据范围。
3. 后端统一实施数据范围、功能权限和联系方式脱敏，不能只依赖菜单隐藏。
4. 建立全平台统一的面试官时间看板和数据库级冲突控制。
5. 支持面试官平台账号、站内通知和 Kim 通知。
6. 当前所有候选人沟通和约面均由 HR 完成，不开放候选人端操作。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 平台管理员 | 可查看全部公司数据并配置公司、账号、权限、面试官和日历的内部管理员 |
| 外包公司负责人 | 查看本公司全部数据并管理本公司账号的外包公司账号；业务能力仍受功能权限控制 |
| 外包公司普通账号 | 只查看和处理自己负责的应聘记录，能力由业务线和功能权限共同决定 |
| 面试官账号 | 查看本人面试和日历、填写本人面评、接收站内与 Kim 通知的账号 |
| 公司权限上限 | 平台管理员允许某外包公司分配给内部账号的最大权限集合 |
| 实际功能权限 | 单个账号最终获得的功能权限，必须是公司权限上限的子集 |
| 应聘记录负责人 | 当前负责候选人招聘推进、约面和线下通知的 HR 账号 |
| 时间占用 | 有效面试或不可用事件占据的面试官时间区间，包含前后缓冲 |

## 3. 账号与数据权限

### 3.1 平台管理员

平台管理员可以：

- 查看所有外包公司的候选人、应聘记录、面试、面评、Offer、入职和接待数据。
- 创建每家外包公司的负责人账号。
- 配置外包公司的权限上限。
- 配置账号的业务线权限和功能权限。
- 创建和管理面试官账号及 Kim 绑定。
- 配置面试官工作日、工作时间、不可用时间和周期事件。
- 查看全平台时间看板及所有预约详情。
- 重新分配任意应聘记录的负责人。
- 只读模拟某家外包公司的实际登录视角。
- 查看授权、分配、约面、改期、取消和状态流转审计记录。

### 3.2 外包公司负责人

外包公司负责人：

- 只能访问本公司数据。
- 可以查看本公司全部应聘记录，不受单个负责人限制。
- 可以创建、停用和重置本公司普通账号。
- 可以分配本公司应聘记录负责人。
- 可以在公司权限上限内为本公司账号授权。
- 不能授予本公司尚未获得的权限。
- 是否能导入、约面、操作 Offer、确认入职等，仍取决于本人实际功能权限。
- 看得到数据不等于可以修改；无相应功能权限时只读。

### 3.3 外包公司普通账号

普通账号：

- 只能访问自己负责的应聘记录。
- 只能处理被授权的业务线。
- 只能执行已授予的功能权限。
- 不能查看同公司其他普通账号负责的候选人详情。
- 不能自行转移负责人或管理账号。
- 不能通过请求参数、其他公司的 ID、导出接口或直接 API 绕过范围限制。

### 3.4 面试官账号

面试官账号可以：

- 查看自己的面试列表和时间看板。
- 查看本人面试所必需的候选人、岗位、轮次和时间信息。
- 填写本人结构化面评。
- 接收预约、改期和取消的站内通知与 Kim 通知。

面试官账号不能：

- 查看与自己无关的候选人和面试。
- 查看外包公司综合看板或其他面试官的完整预约详情。
- 操作 Offer、入职或外包公司账号。

## 4. 权限模型

### 4.1 授权链路

```text
平台管理员配置公司权限上限
              ↓
外包公司负责人只能在上限内授权
              ↓
账号获得实际功能权限
```

后端必须验证：

```text
账号实际权限 ⊆ 公司权限上限
```

外包公司负责人不能通过直接请求授予越界权限。

### 4.2 第一版权限清单

| 权限编码 | 权限名称 | 默认 |
|---|---|---|
| `CANDIDATE_VIEW` | 查看候选人 | 关闭，由管理员配置 |
| `CANDIDATE_CREATE` | 新增候选人 | 关闭 |
| `CANDIDATE_IMPORT` | 导入候选人 | 关闭 |
| `CANDIDATE_EDIT` | 编辑候选人 | 关闭 |
| `CANDIDATE_CONTACT_VIEW` | 查看完整手机号和邮箱 | 关闭 |
| `SCREENING_SUBMIT` | 提交简历筛选结果 | 关闭 |
| `INTERVIEW_VIEW` | 查看面试和时间看板 | 关闭 |
| `INTERVIEW_SCHEDULE` | 安排、改期和取消面试 | 关闭 |
| `FEEDBACK_VIEW` | 查看面评 | 关闭 |
| `FEEDBACK_SUBMIT` | 填写面评 | 关闭 |
| `LEVEL_ADJUSTMENT_REQUEST` | 发起职级调整 | 关闭 |
| `OFFER_MANAGE` | 发起、发送和更新 Offer | 关闭 |
| `ONBOARDING_CONFIRM` | 确认入职 | 关闭 |
| `RECEPTION_VIEW` | 查看接待任务 | 关闭 |
| `DATA_EXPORT` | 导出当前数据范围 | 关闭 |
| `SUPPLIER_ACCOUNT_MANAGE` | 管理本公司账号 | 仅外包公司负责人可拥有 |

附加规则：

- 外包公司不允许物理删除候选人；逻辑删除仅平台管理员可执行。
- 外包公司本期只查看接待任务，不完成接待 checklist。
- 薪资和 Offer 金额敏感权限不在本期范围。
- 候选人自助约面权限不出现在当前授权界面。

## 5. 应聘记录归属与负责人

每条应聘记录必须保存：

- 所属外包公司。
- 当前负责人账号。
- 创建账号。
- 创建时间。
- 最近修改账号与时间。

规则：

1. 普通账号手工新增候选人时，自动成为应聘记录负责人。
2. 普通账号导入候选人时，导入人自动成为负责人。
3. 外包公司负责人可以在本公司内重新分配负责人。
4. 平台管理员可以重新分配任意应聘记录。
5. 普通账号不能自行转移负责人。
6. 每次变更记录原负责人、新负责人、操作人、操作时间和原因。

同一候选人被不同公司提交时：

- 各公司拥有相互隔离的应聘记录。
- 外包公司不能获知其他公司是否提交过该候选人。
- 平台管理员可以看到跨公司重复风险。
- 候选人身份可以去重，应聘记录必须按公司隔离。

## 6. 联系方式脱敏

没有 `CANDIDATE_CONTACT_VIEW` 权限时：

```text
手机号：138****5678
邮箱：z***@example.com
```

该限制必须同时应用于：

- 候选人列表和详情。
- 搜索结果。
- 自动看板候选人明细。
- API 返回值。
- Excel 导出。

拥有 `DATA_EXPORT` 但没有 `CANDIDATE_CONTACT_VIEW` 时，导出内容仍然脱敏。

## 7. 管理员模拟外包公司视角

- 模拟视角必须只读。
- 页面顶部持续显示当前模拟公司。
- 菜单、数据、看板和时间看板按目标公司的真实范围展示。
- 模拟状态下禁止新增、修改、导入、导出、约面和 Offer 操作。
- 退出模拟后恢复管理员权限。
- 进入和退出模拟视角记录审计日志。

## 8. 面试官档案与工作时间

面试官档案包含：

- 姓名、部门、业务线、可面试岗位。
- 平台登录账号。
- Kim 用户标识。
- 工作日、每日开始时间、每日结束时间。
- 启用状态。

默认规则：

- 默认工作日：周一至周五。
- 默认工作时间：09:00–21:00。
- 周六、周日默认不可预约，管理员开启后才能预约。
- 管理员可以单独修改每位面试官的工作日和工作时间。
- 法定节假日和特殊休息通过不可用时间配置。

全平台统一固定休息：

- 11:50–13:30。
- 18:00–18:30。

固定休息只在面试官配置为工作日的日期生效。

## 9. 时间看板

时间看板按面试官展示，支持：

- 日视图和周视图。
- 日期切换。
- 业务线、面试官筛选。
- 可预约、已占用、固定休息和不可用时间展示。

可见性：

- 普通账号看自己负责记录的预约：完整详情。
- 普通账号看同公司其他负责人或其他公司的预约：仅“已占用”。
- 外包公司负责人看本公司预约：完整详情。
- 外包公司负责人看其他公司预约：仅“已占用”。
- 面试官看自己的预约：完整详情。
- 平台管理员看全部预约：完整详情。

## 10. 排期规则

- 每场面试固定 30 分钟。
- 每场面试前后保留 10 分钟缓冲。
- 每场只有一位面试官。
- 可预约开始时间按半小时刻度展示。
- 第一版不连接外部日历。
- 不使用临时 20 分钟锁定。

严格重叠规则下：

- 上午最后一场为 11:00–11:30。
- 下午第一场为 13:30–14:00。
- 晚休前最后一场为 17:00–17:30。
- 晚休后第一场为 18:30–19:00。
- 11:30–12:00 与固定休息重叠，不可预约。
- 17:30–18:00 的结束后缓冲与固定休息重叠，不可预约。

## 11. HR 约面流程

候选人不登录平台，也不在平台选择或确认时间。

```text
HR 与候选人线下沟通
        ↓
HR 打开面试官时间看板
        ↓
选择面试官和可用时间
        ↓
填写应聘记录、岗位和轮次
        ↓
点击确认安排
        ↓
后端进行全平台原子冲突检查
        ↓
创建正式面试并占用时间
        ↓
HR 线下通知候选人
```

约面范围：

- 普通账号必须有 `INTERVIEW_SCHEDULE`，且只能为自己负责的应聘记录约面。
- 外包公司负责人必须有 `INTERVIEW_SCHEDULE`，可以为本公司任意应聘记录约面。
- 平台管理员可以为任意应聘记录约面。
- 无 `INTERVIEW_SCHEDULE` 时只能查看时间看板。

## 12. 数据库级防冲突

最终提交时必须：

1. 对面试官资源加数据库事务锁。
2. 检查面试官工作日和工作时间。
3. 检查固定休息。
4. 检查管理员配置的不可用时间。
5. 检查现有有效面试及前后 10 分钟缓冲。
6. 无冲突时创建面试并写入审计记录。

A、B 两家公司同时提交相同时间时，只允许先获得锁的一方成功；另一方返回：

```text
该面试官的时间刚刚已被占用，请重新选择
```

## 13. 占用、释放和改期

占用时间的状态：

- 已安排。
- 已创建会议。
- 进行中。

释放时间的状态：

- 已取消。
- 候选人拒绝。

改期顺序：

1. 锁定面试官。
2. 检查新时间。
3. 成功后更新到新时间。
4. 原时间随更新自动释放。
5. 写入改期审计。
6. 发送通知。

不能先释放旧时间再尝试新时间。

## 14. 不可用时间

管理员可以配置：

- 请假。
- 内部会议。
- 培训。
- 午休。
- 临时不可用。
- 其他。

支持：

- 单次不可用时间。
- 按周重复的周期不可用时间。
- 生效日期和结束日期。
- 修改、取消和审计记录。

外包公司只看到“不可预约”，管理员和本人可以看到具体原因。

## 15. 通知

预约成功、改期和取消后：

- 当前应聘记录负责人：收到站内通知。
- 面试官：收到站内通知和 Kim 通知。
- 平台招聘管理员：后台可查看，不要求逐条推送。
- 外包公司负责人：除非本人是负责人，否则不主动通知。
- 候选人：由 HR 线下通知，平台不发送。
- 其他外包公司：不通知。

通知记录必须包含接收人、渠道、类型、发送时间、结果、失败原因、应聘记录、面试和幂等键。

## 16. 候选人自助约面

现有代码保留，但本期默认禁用：

- 前端隐藏入口。
- 权限界面不展示。
- 后端接口受功能开关控制。
- 生产环境默认关闭。
- 后续迭代可以重新启用。

## 17. 本期不处理

- 候选人登录、自助选时或在线确认。
- 20 分钟临时时间锁定。
- 企业微信、飞书、Outlook 等外部日历同步。
- 多面试官联合面试。
- 历史面试官数据自动迁移。
- 薪资和 Offer 金额权限。
- 短信或邮件通知候选人。

## 18. 验收标准

1. 外包公司普通账号无法读取同公司其他负责人或其他公司的候选人详情。
2. 外包公司负责人能查看本公司全部数据，但不能跨公司访问。
3. 负责人不能授予超过公司权限上限的权限。
4. 缺少功能权限时，前端入口隐藏且后端接口返回禁止访问。
5. 缺少联系方式权限时，列表、详情、API 和导出全部脱敏。
6. 管理员模拟公司视角时只能读取，不能执行写操作。
7. A 公司约定某面试官 10:00 后，B 公司只能看到“已占用”且无法重复预约。
8. 两个并发请求预约同一面试官相同时间时，最多一个成功。
9. 固定休息、非工作时间和管理员不可用时间均不能预约。
10. 取消后时间释放；改期失败时原时间不丢失。
11. 普通账号只看到自己预约的详情，其他预约只显示占用。
12. 面试官只看到本人日历和面试，并收到站内与 Kim 通知。
13. 候选人自助约面入口和接口在默认生产配置下不可使用。
14. 权限、负责人、约面、改期、取消和不可用时间变更均可审计。
